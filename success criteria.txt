Success criteria (planned, may change)
════════════════

1. An administrator can create and manage user roles, granting them either teacher or student roles.

2. Users (teachers, students, admins) can register and login using email and password, with email verification required before access is granted.

3. A teacher can create, edit and delete classrooms, and add or remove students from them.

4. A teacher can create, edit and delete assignments, attaching at least one of the following: text description, file (PDF, document, image, code), or external link.

5. A student can view all assignments in their enrolled classrooms and mark each as: not started, in progress, completed, or needs help.

6. A teacher can view a summary of all students' completion statuses for any given assignment, showing counts per status category.

7. A student can view their own overall completion rate (as a percentage) across all assignments in a course.

8. A teacher can create and manage a content library of materials (notes, files, links) organised by unit or topic, visible to enrolled students.

9. A student's homepage displays a calendar with upcoming assignment deadlines and a notification panel showing new assignments and teacher comments.

10. An admin can send a system-wide message visible to all users: immediately if the user is logged in, or upon their next login.

11. All user data is stored persistently in a database, and the application can be self-hosted by a school on their own server.
